## 2. 已确认的官网框架

### 导航与产品入口

- 保留产品、定价、文档、博客、活动、企业版；GitHub 保持现有 Star 图标展示。
- 导航右侧提供“登录”入口。
- 取消独立“下载安装”导航。
- 产品顺序暂定为：**CoStrict Cloud -> CoStrict CLI -> IDE 插件**。
- 三种产品形态分别进入自己的产品页；产品页自己承接进入 Web 或安装动作：
  - Cloud：进入 Web。
  - CLI：使用 `csc` 安装命令。
  - IDE 插件：进入对应安装路径。
- 首页集中表达通用产品能力、价值和差异化；产品页不重复承担完整平台介绍。

### 首页第一期

- 首页优先改版，收敛为 6 屏。
- 首页目标不是功能罗列，而是帮助访客理解产品能力、价值和差异化，并完成下一步。
- 首屏保留两个同级动作：**下载**、**进入 Web**。
- 首屏“下载”点击后展开 IDE、CLI 两个入口，分别直达对应产品页的安装方式位置；Cloud 不放入下载菜单，由“进入 Web”承接。
- “进入 Web”进入现有 Web 体验；导航“登录”进入现有 Web 登录。官网只提供入口和页面状态，登录后的身份识别、回跳与账号状态由 Web 端承接。
- 首页应承接进入产品页、下载、进入 Web、企业咨询等关键下一步；衡量时关注这些行为，而不只看首页点击。
- 首页 6 屏的信息顺序已确认，按“先理解，再进入”的逻辑组织：
  1. 顶部信息区：可选活动公告条、导航、GitHub Star 图标、登录和企业版入口。
  2. Hero：产品定位、组织价值说明，以及“下载”“进入 Web”两个同级 CTA。
  3. 三种产品形态：**CoStrict Cloud -> CoStrict CLI -> IDE 插件**；先说明使用环境，再进入对应产品页。
  4. 平台化能力总览：说明 CoStrict 不只是个人编程工具，也是帮助组织沉淀、复用和治理 AI 研发能力的平台。本屏是首页重点；首期只展示 3-5 项经确认可公开、且有真实证据支持的能力。
  5. 核心价值与使用效果：解释组织能力、全流程 AI、风险控制和持续进化；效果证据只使用已确认可公开的内容。
  6. FAQ 与页脚：承接下载安装、登录、数据安全、支持等高频疑问；不替代价格页或 Web 端的真实账号、订单和额度功能。
- 上述顺序和每屏承担的问题已确认。标题、副标题、卡片短文案和能力名称先以《文案》作为设计工作稿；后续内容变更按文案调整，不阻塞首页结构和样式设计。效果数据和最终视觉素材仍需确认，不自行补写为正式对外承诺。

### 企业、定价与账号链路

- 企业版独立成页，重点是企业与个人版差异、企业安全/部署信息和咨询入口；通用能力仍以首页为主。
- 企业线索的目标链路：表单提交成功态 -> 企业微信二维码 -> 内部可跟进的线索接收路径。
- 中文站保留公开价格；国际站不显示价格导航，也不开放订阅。
- 价格页需要在当前页完成登录，并保留用户已选套餐；避免跳转外部登录页后丢失购买任务。
- 支付失败或取消时，保留套餐选择，并提供重试或支持入口。
- 购买成功后的通知、额度、订单和个人中心暂不由官网承接，待 Web 端账号与个人中心打通后再决定。
