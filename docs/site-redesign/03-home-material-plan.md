# CoStrict 首页素材工作清单

> 状态：待产品 / 品牌确认后制作与接入
>
> 目标：让首页每一屏的视觉都能回答文案正在回答的问题。产品入口用真实界面建立可信度；平台能力用可核验的产品证据解释能力；组织价值用独立的抽象图形解释结果，不伪造 UI。

## 1. 总原则

1. **产品入口必须是真实 UI。** 用户正在判断 Cloud、CLI、IDE 分别在哪里使用，不能只用光效或空面板代替。
2. **平台能力优先用真实 UI 局部。** 一张图只证明一个能力和一个可见结果，不拼成“功能墙”。
3. **组织价值使用抽象系统图。** 这一屏解释的是协作、交付、沉淀和治理带来的组织结果，不应假装成某个尚未确认的产品页面。
4. **没有产品证据的能力先不展示。** 不用抽象图代替未确认的功能承诺，尤其是安全扫描和研发效能度量。
5. **先完成公开脱敏，再做裁切和动效。** 模型名、用户名、绝对路径、项目名、客户数据、代码内容和业务文案均不得直接带入官网。

## 3. 现有素材处理结论

### 可作为候选来源

- Cloud：`src/assets/cloud/section-ch-en/section1-ch.png`、`src/assets/section2/task-list-zh.webp`、`src/assets/section2/workspace-list-zh.webp`。
- IDE / 任务过程：`src/assets/strictMode/strict_mode_zh_buffer.webp`。
- Code Review：`src/assets/codeReview/codereview_buffer.webp`。

它们能帮助确定截图构图和产品证据的方向，但不等于已经获准公开。每张图都需要产品负责人确认对应能力仍存在、内容可公开且文案没有超出画面证据。

### 不建议继续使用

- `src/assets/home/redesign/value-placeholder.webp`：纯蓝色波纹没有表达“组织协同、交付、沉淀、治理”中的任何一个结果，不适合作为价值卡片主视觉。
- `src/assets/home/redesign/cli-placeholder.webp`：当前文字可读性差，且露出了本地用户名、目录与模型名；应以它的暗底终端构图为参考重新制作。
- 平台能力区当前的 CSS 点、线和空卡片：只能承担过渡动效，不能作为能力证据的主画面。

## 4. 拍摄与制作规范

### 真实 UI 截图

- 只拍一个明确的“任务正在发生”状态：进行中的任务、可复用的 Agent / 知识项、已发现且可审阅的问题，或已连接的工作空间。
- 截图前使用专门的演示项目与演示账号；项目名、路径、任务、代码、文件、模型和统计数字均应是可公开的演示数据。
- 不压缩整页 UI。先保留能解释文案的局部，再在官网中用浏览器 / 终端外框承接。
- 导出一份不带外框的原始 PNG 和一份用于网页的 WebP；网页图的尺寸不小于展示尺寸的 2 倍。

### 抽象价值图

- 统一为深墨蓝底、低密度青蓝状态光和清晰的信息层级；图形是任务、关系、阶段和检查点，不是装饰性的宇宙、光球或泛科技波纹。
- 抽象图中不放产品按钮、伪造表格、虚构指标或无法解释的英文代码。图必须能在不看文案时看出“协作 / 流转 / 累积 / 关卡”中的一个动作。
- 先制作静态主图；只有当动效能解释状态流转时再补 4-6 秒的轻量循环动画，并提供静态降级图。

## 5. 最小可用素材包

首版不需要一次补齐 12 张。先完成下面 7 项，就能让首页从占位状态进入可评审状态：

1. Cloud 工作区真实截图。
2. 干净的 CLI 任务截图。
3. 干净的 IDE 任务截图。
4. Agent / Skill 管理截图。
5. 知识检索或调用截图。
6. “AI 进入研发交付”的抽象流程图。
7. “经验沉淀”或“质量关卡”的抽象图。

安全扫描与研发效能度量等到能力公开范围、演示环境和截图一起确认后再补。这样既不会因素材缺口卡住首页，也不会用漂亮但没有证据的图替代产品事实。

## 6. 需要确认的单点

请产品 / 研发在交付截图前给每项素材一个明确结论：**能力仍存在、页面当前可用、截图可公开、文案不超出截图证据**。其中任一项不满足，就将该项从首页首版移除或改为不作能力承诺的组织价值图。
